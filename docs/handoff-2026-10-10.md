## Reading the renders

`*_bones.obj` renders paint each TRIANGLE one flat colour (dominant bone of
its corners) - borders look zigzag after subdivision; that is the picture,
not the rig. To see the real skinning, write an OBJ with per-vertex colours
blended from the weights (`v x y z r g b`, see the snippet that produced
`tools/rig_verify/tpose/weights_front.png`) and render it with
`tools/render_groups.py`: it switches Workbench to VERTEX colours
automatically. Those gradients are what the game interpolates.

## Gotchas learned today

- Bash tool heredocs here lose one level of backslash escaping: Python
  patch scripts containing Windows paths (`C:\Users...`) must be written
  with the Write tool to a file and run with `python3 -I file.py`, not
  piped through a heredoc.
- Blender OBJ import defaults to Y-up: always
  `bpy.ops.wm.obj_import(filepath=..., forward_axis="Y", up_axis="Z")`.
  Camera clip_end must be raised for wide multi-model renders.
- `python3` is the working interpreter (3.14); Blender 3.6 is the headless
  one used by the pipeline (5.2 is also installed).
- `build_rig_mixamo.py` prints `clearance:` lines when the overlap resolver
  moved a box and `!! unresolved` if it could not; check them after every
  header regen. Also check `per-bone verts` has no zeros in the first 12.
- `tpose_rig.py` prints `arm<->leg weight leaks: N` per model; it must be 0.
- The physics skeleton uses 12 bodies (feet folded into shins) and
  `CANONICAL_MASS` from `build_rig.py`; joint anchor order is the 13-entry
  `JOINT_BONES` list in `build_rig_mixamo.py` (pelvis-spine, spine-neck,
  neck-head, shoulder L/R, elbow L/R, hip L/R, knee L/R, ankle L/R).
